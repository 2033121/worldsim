# 小说创作功能与界面优化 — 实现方案

> 项目：WorldSim 统一前端（worldapp）
> 范围：小说创作应用（novel）+ 首页（home）
> 日期：2026-08-05

## 1. 目标

针对用户反馈，完成以下四类优化：
1. 小说创作页面功能增强：扩充内容显示区、修复失效按钮、优化按钮设计、实现正文编辑。
2. 首页界面优化：重新设计布局与视觉，提升导航清晰度与交互体验。
3. 技术完备：稳定可靠、界面友好、操作流畅、可维护可扩展。
4. 交付：完整方案文档 + 可运行实现 + 测试报告。

## 2. 现状诊断

调研结论（基于源码 + 运行验证）：

### 2.1 失效按钮（关键 Bug）
novel 路由已从「hash 路由」迁移为「store 驱动」（`lib/router.js` 的 `currentPage`），但以下按钮仍用 `window.location.hash = '#x'` 导航，**点击无任何效果**：

| 文件 | 行号 | 失效操作 |
|---|---|---|
| `Writing.svelte` | 394 | `#outline`（未就绪跳转大纲） |
| `Writing.svelte` | 469/492 | `#foreshadows`（跳转伏笔） |
| `Outline.svelte` | 133 | `#writing`（大纲确认后跳写作） |
| `Foreshadows.svelte` | 49 | `#outline`（跳转大纲） |

修复：统一改为 `navigate('outline'|'foreshadows'|'writing')`。

### 2.2 内容显示区受限
写作页正文容器 `max-h-[calc(100vh-420px)]`，且为 `grid-cols-[230px_1fr]` 固定两栏，正文高度受限，长文展示不完整。

### 2.3 编辑能力
后端已具备完整能力：
- 块级编辑：`PUT/DELETE /api/chapters/{num}/blocks[/{id}]`、`POST .../blocks`（插入）、`POST .../blocks/{id}/revise`（AI 修订）。
- 整章编辑：`POST /api/chapter/edit`，支持 `EditOpReplaceText`（全文替换）、`EditOpReplaceLines`（行区间替换）等操作（`internal/story/editing.go`）。
- 前端目前仅暴露「块级编辑」，缺少一键「整章全文编辑」。

### 2.4 首页
当前首页较朴素：标题 + 2 个快捷入口卡片 + 可用页面标签。缺少状态展示、最近访问、更清晰的视觉层次。

## 3. 技术选型

| 层 | 选型 | 说明 |
|---|---|---|
| 前端框架 | Svelte 5 + Vite | 与现有 worldapp 一致，天然集成 |
| 样式 | Tailwind CSS v4 + daisyUI | 现有宣纸水墨主题（`app.css`） |
| 状态 | Svelte store | 沿用 `lib/stores.js`、`lib/router.js` |
| 后端 | 现有 Go 服务（:48090） | **零新增后端接口**，复用已有 API |
| 构建 | Vite → `uiteg/` → Go embed | 现有流水线 |

**关键决策：不新增后端接口**。整章编辑复用 `POST /api/chapter/edit` + 块级编辑，避免扩展后端、降低回归风险。

## 4. 架构设计

### 4.1 写作页（Writing.svelte）结构
```
┌ 进度卡（生成/确认/导出/冲突） ┐
├ 伏笔卡、后处理卡 ─────────────┤
├ 章节区 ──────────────────────┤
│  ├ 章节列表（左）              │
│  └ 内容区（右）                │
│     ├ 标题/状态/字数           │
│     ├ 大纲/摘要折叠            │
│     ├ 正文区（块级 or 整章编辑）│
│     └ 操作栏（生成/确认/修订/润色/复制/上一章/下一章）│
└──────────────────────────────┘
```

### 4.2 整章编辑模式（新增）
- 新增「整章编辑」按钮（仅正文非空时显示）。
- 点击进入编辑态：正文区切换为大 `textarea`（绑 `chapterContent`）。
- 保存：调用 `POST /api/chapter/edit`，`operation=replace_text`，`old_text=保存前快照`、`new_text=编辑后文本`。
- 取消：恢复快照，退出编辑态。
- 编辑态与块级编辑互斥（进入整章编辑时清空块级编辑状态）。

### 4.3 按钮设计规范（统一）
- 主操作（生成/确认）：`btn btn-primary btn-sm`，带图标。
- 次操作（修订/润色/复制/导出）：`btn btn-ghost btn-sm`，带图标 + 文字。
- 危险操作（删除）：`btn btn-ghost btn-sm text-error`。
- 分页（上一章/下一章）：`join` 分组。
- 统一 `gap-2`、`flex-wrap`，保证窄屏换行。

### 4.4 首页重构
```
┌ Hero 区（logo + 标题 + 副标题 + 快捷键提示） ┐
├ 快捷入口（2 大卡片：世界模拟 / 小说创作）──────┤
├ 三栏功能导览（不同页面分组）────────────────┤
├ 能力亮点（标签组：多标签/书签/命令面板/主题）─────┤
└ 状态/最近（可选占位）───────────────────────┘
```

## 5. 开发步骤

1. **修复失效按钮**：Writing/Outline/Foreshadows 的 `window.location.hash` → `navigate()`。
2. **扩充内容区**：调整正文容器高度（`max-h-[calc(100vh-360px)]` 或自适应），优化两栏比例。
3. **整章编辑**：新增 `chapterEdit` 状态 + 编辑/保存/取消逻辑，复用 `POST /api/chapter/edit`。
4. **按钮视觉优化**：统一图标、层次、间距。
5. **首页重构**：新布局 + 三栏导览 + 亮点标签。
6. **构建部署**：`npm run build` → Go 交叉编译 → `docker cp` → 重启。
7. **验证**：Playwright 脚本实测各功能 + 无 404 + 无 JS 报错。
