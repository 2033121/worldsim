# 同类项目调研 → v1.9.0「游玩页世界观感 + 世界卡」规划

（2026-09-12 调研；对象：SillyTavern / talemate / SillyTavern 状态追踪扩展生态 / AI-Dungeon 同类开源引擎）

## 一、调研对象与可借鉴结论

### 1. SillyTavern（LLM 前端事实标准，docs.sillytavern.app）
- **World Info（Lorebook）动态注入引擎**：条目=关键词(支持正则)+内容+插入位置+插入顺序；扫描最近 N 条消息命中即注入上下文。核心机制：
  - **Scan Depth**：只扫最近几条，控成本
  - **递归激活**：条目内容可激活其它条目（限步数）
  - **Timed Effects**：sticky（命中后保持 N 条消息）/ cooldown（冷却）/ delay
  - **Token 预算**：激活条目总量有上限，超限截断
  - **中文警示**：whole-word 匹配对 CJK 有害——必须用子串匹配
- 对 worldsim：世界书目前是"静态分段注入 + E 层事件触发"，缺**关键词级动态注入**——游玩时裁判/叙述者应该按"最近回合里提到了谁/什么"动态获得对应 lore。
- 借鉴取舍：不搬正则/递归/Inclusion Group（复杂度高收益低）；搬 **keys + scan depth + sticky + token 预算 + 子串匹配**。

### 2. talemate（vegu-ai/talemate，419★，AGPL，Python）
"Roleplay with AI with a focus on strong narration, consistent world and game state tracking"：
- **Agent 家族化**：dialogue/narrator/summarize/director/editor/world_state/creator/visual/tts/memory，各 agent 可独立选模型
- **World State Agent**：持续维护角色/世界事实，叙述时强制"世界真相"注入
- **Visual Agent**：场景/角色图像生成直接进叙事界面
- 对 worldsim：多 agent 分层与"世界真相由代码/专用 agent 持有"的纪律我们已有（且更硬：数值层纯代码）；差距在**视觉 agent 的成果没有进入游玩界面**——我们已生成 63 个 sprite/世界，但游玩页只用了 hero+monster 两张。

### 3. SillyTavern 状态追踪扩展生态（WTracker 39★ / SimTracker 63★ / BetterSimTracker / statspanel）
- 通用模式：LLM 每回合输出结构化 JSON 状态增量 → 扩展解析 → **视觉状态卡**（HP 条/属性/背包/关系图）→ 再把状态模板化注回 prompt
- 对 worldsim：状态收数我们已经在代码层（比它们可靠，LLM 无法篡改）；**视觉呈现与关系追踪**是短板。BetterSimTracker 的"关系/好感度逐回合追踪+注回 prompt"直接可抄。

### 4. AI-Dungeon 同类小引擎（vkhanht1/LLM-DM、Hokken/interactive-fiction 等）
- Hokken 用向量检索做 lore 增强 + 输入护栏；vkhanht1 用 JSON 状态块让 LLM 记状态——都是我们把状态放代码层的弱化版，验证了方向，不必借鉴。

## 三、完整性评判（第一版计划的漏洞与修补）

1. **漏：中文匹配策略**——ST 文档明示 whole-word 匹配毁中文 → 明确"子串匹配 + 中文逗号分隔 keys"，写入引擎注释与模板。
2. **漏：注入预算与抖动**——无预算会撑爆裁判上下文；sticky 缺失会造成条目闪断 → 预算 1200 字符 + sticky 3 回合。
3. **漏：测试策略**——WI 引擎/好感度钳制/地图布局确定性全部要单测（合成世界书 + 断言激活集合；同一 world 状态两次布局必须逐格一致）。
4. **漏：两套 UI 漂移**——game.html 与 GamePage.svelte 功能不同步会割裂 → 明确本轮 game.html 全量、Svelte 只同步"场景横幅+物品图"两项。
5. **漏：地图视图的数据正确性**——LLM 现场编布局不可靠 → 不用 LLM：从引擎 state.Entities 的 location 集合确定性布局；tile 语义用名称关键词映射（水/湖→water、林→forest、山/岩→rock、营/寨→camp、城/镇/村→road…），查不到的按 hash 取安全地。
6. **漏：导出隐私边界**——编年史/记忆可能含私人内容 → 默认不导出，只导世界书+美术+规划（game.json 可选参数）。
7. **漏：模板与文档**——W1 段要有用法示例进 `_template.md`；docs/美术工坊.md、CHANGELOG、README、AGENTS 同步。
8. **漏：E2E 验证链**——单测之外必须跑真回合：W1 条目命中注入可见（日志）、好感度落盘、地图/头像/横幅渲染、世界卡导出→导入→可玩。
