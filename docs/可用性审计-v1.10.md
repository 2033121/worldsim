# 可用性审计与分改进计划（v1.10.0 轮）

> 时间：本轮维护 · 基线：v1.9.0（远端 `06221b8`）
> 方法：逐文件代码审计 → 本地起服实测取证 → GitHub/网络同类项目调研 → 分类改进计划 → 实施。

## 一、审计发现（按维度）

### A. 致命缺陷（可玩性阻塞，已实测证实）
| # | 问题 | 位置 | 实测证据 |
|---|---|---|---|
| A1 | `post()` 把请求路径拼成 `/api/game/action.`（尾点多一个点）→ 落到 `GET /` 兜底返回 **405 Method Not Allowed**；页面所有回合提交必然失败 | `wsweb/game.html` L93 | `curl -X POST /api/game/action.` → `HTTP:405` |
| A2 | `send()` 先 `inp.value=''` 清空输入框，再由 `post()` 重新读取 input 值 → 提交的永远是空字符串；服务端把空输入替换成「原地等待」——**玩家无论输入什么都变成等待** | `wsweb/game.html` L175+L93 | `POST {"input":""}` → 服务端按等待回合叙述 |
| A3 | CSS 规则 `'.chip b{color:var(--acc)}` 首字符多了一个 `'`，整条规则失效（面板数值高亮丢失） | `wsweb/game.html` L19 | — |

> 说明：v1.9.0 的 E2E 是 curl 直打 API 验证的，页面 JS 层从未走过真实浏览器回合——这两个 bug 因此漏网。

### B. 代码实现质量
- **B1 长锁**：`internal/game` 的 `Turn/Wait` 在**整个两次 LLM 调用期间**（最长 300s）持有 `sync.Mutex`；`/api/game/status`、`/api/game/log` 同锁读取 → 回合进行中所有面板请求挂起直到超时。多标签页/轮询场景直接卡死。
- **B2 隐性惩罚**：`Roll()` 中 `mod := attrs[ability]-5`，若裁判申报了面板中不存在的属性 key，玩家吃 -5 修正且无任何提示。
- **B3 死代码**：`studio.html` 的 `label` 变量（怪异 replace 链后未用）、重复 onchange 绑定；`gameCtx` 中 `role` 取值后弃用；`game.html` `renderState` 在 log 循环里逐条重放。
- **B4 重复读盘**：一次 `/api/game/status` 最多触发 5 次 `art.LoadPlan`（assetRoster×4 + mapLayout），plan.json 每次都从磁盘读。
- **B5 任务轮询叠加**：studio.html 每次提交生成新建 `setInterval`，重复提交会叠出多个并行轮询。
- **B6 规划生成失败静默**：`btnPlanGen` 不检查 POST 返回，失败也要傻等 90×3s 才报「超时」。

### C. 功能完全性
- **C1 世界卡没有前端入口**：`GET /api/world/card` / `POST /api/worlds/import` 只能 curl（grep 全前端 0 引用）——v1.9.0 主打功能普通用户根本用不到。
- **C2 无存档管理**：没有导出/导入 game.json 的任何途径；换数据目录即丢进度。
- **C3 无撤销/重掷**：同类产品（AI Dungeon 的 Retry/Rewind、chasm_client 的 character state 管理）都把「后悔药」当核心体验；本实现一回烂骰只能认。
- **C4 无失败终点**：HP 可被钳到 0 但游戏继续，无「倒下」状态与恢复路径。
- **C5 世界时钟冻结**：游玩期间后台循环暂停、引擎 day 不动 → 场景横幅 day%3 永不轮转、游戏日志 day 恒等于进入时的 day（wait 的 day+1 只写在日志里）。
- **C6 WI 触发黑盒**：动态情报命中只打在服务端 stdout，玩家完全不知道哪条 lore 生效了。

### D. 可玩性 / 游戏感
- D1 掷骰结果纯文字，无 d20 动画——「命运在骰子上」但骰子毫无存在感。
- D2 检定失败会把主角 sprite **永久换成怪物图**（`applyMonsterOnFail`），且无任何恢复——资产语义误用 + 诡异体验。
- D3 HP 条颜色恒定（渐变色条与血量无关）；XP 无进度可视化。
- D4 输入无历史（↑/↓），长句重打成本高。

### E. UX / 前端一致性
- E1 `game.html`「开始/重开」对**已开局的世界直接清空重开**，无确认；开局成功后不调 `refresh()`——场景/地图/crew 全部空白直到手动刷新。
- E2 `worldChip` 永远显示「世界：」（`(r.day!=null?'':'')` 恒空）。
- E3 **48091 与 48092 双控制台漂移**：`:48091/` 服务的是 wsweb/assets 里的**旧版构建**（index-BrjSftAN.js），与 uiteg 统一外壳（index-B9DreMlZ.js）功能集完全不同，用户从不同端口进来看到两个产品。
- E4 Svelte GamePage 与 game.html 特性不对齐：无关系徽章、无地图 NPC pin、开局后同样不刷新观感字段。
- E5 无 favicon；busy 状态不禁用「等待」按钮。

## 二、分改进计划

**A 类 · 致命修复（game.html）**：post() 改为正确路径并显式传参；send() 闭包传值；CSS 修复。

**B 类 · 代码质量**：game 包改为「短锁快照 → 无锁 LLM → 短锁提交」+ `turning` 单飞标志（并发回合 409）；Roll 属性校验（未知属性 mod=0）；删死代码；plan.json TTL 缓存（10s）；studio.html 轮询单例化 + POST 错误直报。

**C 类 · 功能补全**：
1. **世界卡 UI**（uiteg 控制台新组件 CardPanel：导出可选含进度 / 导入上传 + toast）；
2. **存档**：`GET /api/game/export`、`POST /api/game/import`（校验+clamp）+ 两侧 UI 按钮；
3. **撤销一步**：Turn 前深拷贝 state → `prev`（随 game.json 落盘），`POST /api/game/undo` 回滚（单步，不叠栈）；
4. **倒下状态**：HP=0 → `downed=true`；等待回合恢复 25% 解除；裁判/叙述 prompt 感知；UI 横幅；
5. **时钟同步**：wait 后引擎 Day 同步推进（模拟器同款直接改 + Save），场景轮转生效；
6. **WI 透明化**：status 返回 `wi_hits`，UI 显示「🔎 情报：…」chips。

**D 类 · 游戏感**：d20 结果行加滚动动画；删 applyMonsterOnFail 改 shake；HP 条按血量变色；XP 进度条；输入历史 ↑/↓。

**E 类 · UX 一致性**：开局 confirm + 成功后 refresh；worldChip 显示世界名+Day；48091 根路径改服务 uiteg 外壳（`/assets/{f}` 路由 + SPA fallback），删除 wsweb/assets 旧构建；Svelte 对齐（relations/NPC pin/day/开局刷新）；favicon。

**F 类 · 文档**：CHANGELOG [1.10.0]；README 中英；AGENTS.md；测试（undo/downed/单飞/存档校验）。

## 三、完整性自评（修补记录）
1. undo 不回滚 wiSticky 计数 → 接受（lore 注入无破坏性）；
2. undo 快照若含 200 条日志会使 game.json 膨胀 → **单步撤销**方案（只存 1 份 prev）；
3. downed 与 `clamp()` 交互：判定放 clamp 之后（HP==0）；
4. plan TTL 缓存可能让工坊改动延迟生效 10s → 窗口可接受，注释说明；
5. 并发回合 409 需要前端友好提示（busy 已禁按钮，双标签兜底显示错误文案）；
6. 48091 改服务 uiteg 后旧书签直达控制台仍可用（API 同源、SPA 客户端路由接管）；
7. 导入存档必须先 start? 否——导入后 enabled 状态由文件决定，前端 load() 即可；
8. syncGameToEngine 在 downed 时 health=0 → 播种链路读到濒死主角，语义正确；
9. uiteg 改动后需 `npm run build`，embed 是目录级无需动 main.go 的 embed 声明；
10. game.html 的 log 全量重渲染保留（200 条上限、终端风可接受），但 renderState 移出循环。

→ 修补后无未决项，进入实施。

## 四、实施结果（本节为完成后补记）

- A1/A2/A3、B1-B6、C1-C6、D1-D4、E1-E5、F1-F3 **全部落地**；一处计划外发现与修复：
  - **布局级 bug（新增 E6）**：`body` 为 flex column 时所有 `margin:0 auto` 的子块收缩为内容宽（场景横幅竖图缩成 ~60px 窄条最刺眼）——flex item 的 auto margin 会吞掉 cross-axis stretch。居中行容器统一补 `width:100%`，场景横幅改固定 `height:96px + object-fit:cover` 全宽铺满（修复前后浏览器截图对比已存档）。
  - `GET /{path...}` 与 `GET /` 在 Go 1.22 mux 冲突会 panic（构建期不报错、启动期才炸）——合并为单一 catch-all，根路径在 handler 内处理。
- 实测结果见 CHANGELOG [1.10.0] 验证节；undo/downed/单飞/存档均有单测，页面层有真实浏览器截图取证。
